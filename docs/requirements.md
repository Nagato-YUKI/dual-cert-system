# 学生校内双证管理系统 — 项目需求文档

## 一、项目概述

### 1.1 项目名称

学生校内双证管理系统

### 1.2 项目背景

当前学校在证书考试管理方面面临以下痛点：

- **流程分散**：证书报名、审核、考试、发证各环节分散在不同部门，缺乏统一管理平台
- **审核低效**：人工审核报名材料耗时长、标准不统一，易出现错审漏审
- **信息不对称**：学生获取证书考试信息渠道有限，不清楚报考条件、时间、费用等关键信息
- **数据孤岛**：各证书数据独立存储，无法进行统一的数据分析和可视化展示
- **通知滞后**：审核结果、考试提醒等信息依赖线下通知，时效性差

本项目旨在为学校提供一个证书考试全生命周期管理平台，覆盖从证书类型管理、考试发布、学生报名、AI智能审核、人工复核到证书发放的完整流程。

### 1.3 项目目标

1. 实现证书考试全流程线上化、数字化管理
2. 通过 AI 审核提升报名审核效率和准确性
3. 为学生提供便捷的证书信息查询和报名通道
4. 通过数据大屏实现证书数据的实时可视化监控
5. 借助 AI 知识库机器人降低信息查询成本

## 二、核心功能需求

### 2.1 管理员端

| 功能模块 | 功能描述 | 优先级 |
|---------|---------|--------|
| 证书管理 | 证书类型的增删改查，包括证书名称、分类（人社类/专业类/校内引进）、报名条件、考试科目、费用等 | P0 |
| 考试管理 | 考试计划发布、编辑、删除，关联证书类型，设置考试时间、地点、名额 | P0 |
| 审核管理 | AI 审核结果查看、人工复核队列、批量审核操作、审核日志记录 | P0 |
| 数据大屏 | 证书统计、报名趋势、审核通过率、各证书报考人数等可视化图表（ECharts） | P1 |
| 批量导入 | 通过 Excel 文件批量导入学生信息、报名数据 | P1 |
| 操作日志 | 管理员关键操作审计记录 | P2 |

### 2.2 学生端

| 功能模块 | 功能描述 | 优先级 |
|---------|---------|--------|
| 证书浏览 | 按分类浏览证书信息，查看报考条件、考试科目、费用、FAQ 等 | P0 |
| 考试报名 | 选择考试 → 填写报名信息 → 上传材料 → 提交审核，报名按钮状态实时反馈 | P0 |
| 个人仪表盘 | 查看已报名考试、审核状态、历史记录 | P1 |
| AI 引导 | AI 知识库机器人，支持自然语言问答，提供证书推荐、报考指导 | P1 |

### 2.3 系统级功能

| 功能模块 | 功能描述 | 优先级 |
|---------|---------|--------|
| JWT 认证 | 基于 Flask-JWT-Extended 的双角色（admin/student）认证体系 | P0 |
| AI 审核 | 调用 LLM API 对报名材料进行智能审核，返回审核结果、评分、理由和问题列表 | P0 |
| 批量导入 | 基于 openpyxl/pandas 的 Excel 数据批量导入 | P1 |
| 短信通知 | 基于阿里云 SMS SDK 的审核结果通知、考试提醒（支持 Mock 模式） | P1 |
| 知识库机器人 | 基于本地 JSON 知识库的智能问答机器人，支持关键词匹配和上下文理解 | P1 |
| 材料归档 | 报名材料的上传、存储和归档管理 | P1 |

## 三、非功能需求

### 3.1 界面与交互

| 需求项 | 描述 |
|--------|------|
| 响应式布局 | 基于 Bootstrap 5 实现，适配桌面端和平板端 |
| 中文界面 | 全系统中文界面，包括错误提示、状态标签、操作反馈 |
| 统一状态映射 | 所有状态字段统一中文映射（如 pending→待审核、approved→已通过） |
| 内联错误提示 | 登录等表单错误采用内联提示，不使用 alert 弹窗 |

### 3.2 性能与安全

| 需求项 | 描述 |
|--------|------|
| 数据安全 | 密码使用 Werkzeug 哈希加密存储，JWT Token 认证 |
| 环境变量 | 敏感配置（SECRET_KEY、JWT_SECRET_KEY、API Key 等）通过环境变量管理 |
| 文件上传 | 限制上传文件大小（16MB），上传目录安全隔离 |
| SQL 注入防护 | 使用 SQLAlchemy ORM 防止 SQL 注入 |
| CSRF 防护 | Flask 内置 CSRF 保护机制 |

### 3.3 可维护性

| 需求项 | 描述 |
|--------|------|
| 应用工厂模式 | Flask 应用工厂 + Blueprint 路由分模块 |
| 服务层分离 | 业务逻辑封装在 services 层，与路由层解耦 |
| 数据库迁移 | 支持 SQLite → PostgreSQL 平滑迁移 |
| Mock 模式 | AI 审核和短信服务均支持 Mock 模式，便于开发调试 |

## 五、数据模型

### 5.1 核心实体

- **User**：用户账号（admin/student 双角色）
- **Student**：学生信息（关联班级）
- **Class**：班级信息（专业、年级）
- **CertType**：证书类型（分类、报名条件、考试科目）
- **RegistrationRule**：报名规则（关联证书类型）
- **Exam**：考试计划（关联证书类型、时间、地点、名额）
- **Registration**：报名记录（关联学生、考试、审核状态）
- **ReviewLog**：审核日志（AI 审核结果、人工审核记录）
- **CertificateRecord**：证书发放记录
- **TrainingMaterial**：培训材料
- **OperationLog**：操作审计日志

### 5.2 关键关系

```
CertType 1---N Exam          （一个证书类型对应多场考试）
Exam    1---N Registration   （一场考试对应多条报名）
Student 1---N Registration   （一个学生可报名多场考试）
CertType 1---1 RegistrationRule （一个证书类型对应一条报名规则）
Registration 1---N ReviewLog    （一条报名对应多条审核记录）
```

## 六、约束与假设

1. 系统面向校内使用，用户群体为学校管理员和在校学生
2. AI 审核为辅助功能，最终审核决定权在人工审核
3. 短信通知依赖第三方服务（阿里云 SMS），开发环境使用 Mock 模式
4. 知识库数据为本地 JSON 文件，后续可扩展为向量数据库
5. 系统暂不支持在线支付，报名费用线下收取
